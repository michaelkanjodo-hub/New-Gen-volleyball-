Your data, clearly explained.

The site works without a backend. An owner can optionally connect the existing Supabase project to share public community records between devices.

Before a public launch

The current SQL is a permissive prototype, not production access control. Accounts, medical files, and coach feedback need authenticated, private backend storage. New sync writes exclude private fields, but any sensitive data already uploaded under the old setup must be reviewed and protected separately.

  1. Prepare the project.

    Open the existing Supabase project. In SQL Editor, run the project’s supabase-setup.sql file. Review its public access policies before using real personal data.

  2. Connect with the public anon key.

    In Supabase, open Settings → API and copy the public anon key. Never use a service-role key here. This setting is stored only in this browser.

    A browser setting for the website owner—not a player sign-in step.

  3. Know what stays local.

    Public profiles, teams, fixtures, bookings, highlights, chat, support records, and stream links can sync. Account credentials, contact details, medical documents, personal skill history, strategy notes, and player feedback stay in this browser.

    Without sync, another device will not see this browser’s records. Clearing site storage removes local data. Back up important records before changing browsers or clearing storage.

    Disconnecting does not delete local records or remote project data.
